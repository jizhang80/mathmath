## 1. Purpose

Help Ontario grade 9–12 students and their parents with the "falling behind in math" problem.

The product's single differentiator over generic AI chat: **it knows which concept node a student is weak on, why, and which downstream courses that node feeds.** Generic AI explains a problem; this system diagnoses.

Core belief driving the design: any student who wants to learn can master the material with the right method. The right method here is *just-in-time remediation* — keep moving forward on current homework, backfill only the minimum upstream gap when a problem surfaces, then return to the main line.

## 2. Product definition

A student brings a current homework problem. The system:

1. verifies each of the student's steps deterministically (CAS),
2. locates the first wrong or missing step,
3. classifies the error against a fixed per-node error catalogue,
4. walks the cross-grade concept dependency graph to find the deepest unmastered prerequisite (capped at 1–2 levels per session),
5. presents that as a *hypothesis* and confirms it with a ~60-second probe (2 short items),
6. remediates the minimum necessary piece, and
7. returns to the original problem.

Answers are never withheld; what is withheld is *a cost-free answer*. Every answer is accompanied by the diagnosis.

Parents get a separate view: where the student is stuck, why, and whether they are progressing.

## 4. Architecture

### 4.1 Logical layers

```
① Curriculum Spine
   Official expectation nodes keyed by Ministry codes.
   Sources: MTH1W (2021); MPM2D/MFM2P (2005 + 2022 addenda);
   MCR3U, MCF3M, MBF3C, MEL3E, MHF4U, MCV4U, MDM4U, MAP4C, MEL4E (2007).
   [SOURCED: dcp.edu.gov.on.ca; edu.gov.on.ca/eng/curriculum/secondary/math1112currb.pdf]

② Concept Graph                          ← core asset
   Cross-grade concept nodes + prerequisite edges (DAG).
   Every edge carries source, confidence, probe statistics.
   Course = node subset + depth marker. ①→② is many-to-many.

③ Learning Objects
   Per node: explanation, worked examples, error catalogue (enum),
   tiered hint tree, probe item set. Pre-generated static assets.

④ Interaction
   Entry → step verification → localisation → error classification →
   hint → backtrack → probe → remediation → return to main line.
   Plus parent view.
```

### 4.2 Runtime tiers

| Tier | Components | Covers | Marginal cost |
|---|---|---|---|
| 0 Deterministic | MathLive input; Pyodide + SymPy step verification; graph queries; pre-generated hint trees; probes | Menu entry, step checking, standard hints, backtracking, probing | Zero |
| 1 Local model | Chrome Prompt API (Gemini Nano); fallback WebLLM + 3B q4 model on WebGPU | Free-text entry → node mapping; error classification (enum selection); hint wording adaptation | Zero |
| 2 Cloud | Claude API | Queued. Not built in MVP. | Metered |

Rule: any model task with confidence below threshold falls back to Tier 0 deterministic behaviour (offer candidates for the student to pick, give the generic hint). The system never guesses a diagnosis.

### 4.3 Client stack (MVP)

- PWA + Service Worker — offline, asset caching
- MathLive — structured math input → LaTeX
- Pyodide + SymPy — symbolic equivalence, equation solving, domain checks
- IndexedDB — concept graph, student state, probe records
- Chrome Prompt API — classification/rewrite under structured JSON output schema
- WebLLM (fallback) — 3B quantised model on WebGPU
- Static hosting only — no server-side application logic in MVP; L3 telemetry endpoint is the sole write path and is opt-in

Storage budget on the 20 GB baseline: Gemini Nano ≈ 4 GB [SOURCED: press reporting, medium confidence] + app assets < 100 MB [ESTIMATE] + optional fallback model ≈ 2 GB [ESTIMATE: 3B × 4-bit] ≈ 6–7 GB total, leaving > 13 GB — above Chrome's 10 GB free-space threshold below which it evicts the on-device model [SOURCED: developer.chrome.com/docs/ai/prompt-api].

## 5. Concept graph data model

**Node**
- `id`, `name`, `strand`
- `expectation_codes[]` — Ministry codes this node realises
- `courses[]` — each with a `depth` marker
- `error_catalogue[]` — enumerated typical errors (closed set + "none of these")
- `hint_tree` — tiered hints per error type
- `probe_items[]` — short confirmation items
- `paraphrase` — the project's own one-line description (no verbatim Ministry text)

**Edge** (A is prerequisite of B)
- `from`, `to`
- `sources[]` — each tagged: `ministry_prereq` | `textbook_order` | `third_party_structure` | `model_generated`
- `generation_agreement` — number of independent generation runs that produced this edge
- `confidence` — initialised from sources + agreement; updated by probe data
- `probe_stats` — `{probes, confirmed, downstream_fail_given_upstream_fail}`

**Structural constraints (L0, machine-checked, must all pass before any graph is accepted)**
- Acyclic
- No edge from a later course to an earlier course
- Every expectation code maps to ≥ 1 node; every node maps to ≥ 1 expectation code
- In-degree outliers flagged for inspection (threshold to be set empirically at M2)
- Starting chain (D14) is connected end-to-end; no isolated islands

## 6. Verification method

| Layer | Method | Skill required |
|---|---|---|
| L0 | Structural constraints in §5, automated | None (graph theory) |
| L1 | Multi-source agreement: Ministry course prerequisites; Ontario-approved textbook chapter order and "prerequisite review" sections; independently built structures (Khan Academy, OpenStax, CK-12); ALEKS public topic structure. Rule: an edge with ≥ 2 independent sources is accepted. | None (judging agreement, not mathematics) |
| L2 | Multiple independent model/prompt generation runs; intersection accepted; disagreements shipped at low confidence (D13). Optional one-off consultation with an Ontario math teacher, only for edges still unsettled after L3 data accumulates. | Deferred |
| L3 | Empirical: the graph predicts that students failing A fail B at a higher rate. Tested continuously with anonymous probe data (D17). Collection is built in from M3. | None |

Theoretical basis: Knowledge Space Theory (Doignon & Falmagne, 1985); ALEKS has operated on it commercially since the late 1990s [SOURCED: aleks.com; Cosyn et al., J. Math. Psychology 2021]. The field's finding: prerequisite structures are validated by predictive accuracy on student response data, not by expert review.

## 7. Interaction contract (the one flow every milestone must preserve)

```
Student input (menu or structured editor)
  → map to node (Tier 0 menu | Tier 1 free text)
  → CAS verifies each step
  → first failing step located (deterministic)
  → error type classified against node's catalogue (Tier 1) or offered as candidates (Tier 0)
  → tiered hint from hint tree (wording adapted by Tier 1 if available)
  → if error type implies an upstream node: present as hypothesis
  → probe (2 items, ~60 s)
      pass → "not the issue, back to the problem"; log
      fail → minimal remediation on that node; log
  → return to original problem
  → session record updated; parent view reflects node, gap, trend
```

Owner's product-test criteria for this flow (M3 acceptance): reads like a teacher not a chatbot; probe feels like confirmation not interrogation; a wrong hypothesis costs the student one minute and no trust.

## 8. Milestones (ordered; no time estimates)

**M0 — Baseline** ✅ complete
- Decisions D1–D19 locked.

**M4′ — Tier 1 spike** (runs in parallel with M1; result gates nothing before M4)
- Node: logarithmic equation solving. Error enum (6): missed domain restriction; log-combination rule misapplied; exponent–log inverse relationship not internalised; quadratic solved incorrectly; arithmetic slip; none of these.
- Data: synthesise ~30 wrong solutions per error type with a large model (round-trip test) [ESTIMATE: minimum size to reveal confusion patterns]. Synthetic errors are cleaner than real ones, so results are an **upper bound** on accuracy.
- Run Chrome Prompt API with JSON schema output `{error_type ∈ enum, confidence}`.
- Metrics: top-1 accuracy, confusion matrix, "none of these" misuse rate, abstention behaviour at low confidence.
- Go/no-go: top-1 ≥ 80% on synthetic data ⇒ Tier 1 exists [ESTIMATE: owner-set threshold leaving headroom for real-data degradation; not from literature]. Below ⇒ D15 triggers architecture revisit.
- Same session: measure Pyodide + SymPy first-load latency on the baseline machine.

**M1 — Spine + data model**
- Extract all grade 9–12 expectation codes and text into a spine JSON (own paraphrase field populated; verbatim text not shipped).
- Implement node/edge schema (§5) and L0 checker.
- Deliverable: validated empty graph skeleton; L0 checker passing on spine.

**M2 — Concept graph, starting chain v0** (D14)
- Multiple independent generation runs → intersection → L0 → L1 source matching → disputed-edge list.
- Deliverable: starting-chain graph with per-edge sources and confidence; disputed edges present at low confidence.

**M3 — Tier 0 end-to-end prototype**
- MathLive + Pyodide/SymPy + hint trees + probe mechanism + L3 telemetry (opt-in, anonymous).
- One problem on the starting chain runs the full §7 flow with no model.
- Deliverable: demonstrable zero-model product; owner product-test against §7 criteria.

**M4 — Tier 1 integration** (only if M4′ passed)
- Prompt API mapping, classification, wording adaptation with confidence gating and Tier 0 fallback.
- WebLLM fallback path.

**M5 — Parent view**
- Node-level status, gaps, trend, suggested actions. Read-only over session records.

**M6 — Coverage expansion**
- Remaining strands and streamed courses (MFM2P, MCF3M, MBF3C, MEL3E, MCV4U, MDM4U, MAP4C, MEL4E).

**Release** — only after M6.
